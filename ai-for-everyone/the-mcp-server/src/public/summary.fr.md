Rédiger une issue GitHub dans un chat ne suffit pas à la créer dans un dépôt. À travers une intégration GitHub simulée, cette présentation explique comment le Model Context Protocol relie une application utilisant un LLM à des capacités externes, en distinguant les rôles du modèle, du client MCP et du serveur.

Avec la révision MCP 2026-07-28, les échanges JSON-RPC 2.0 permettent de suivre la découverte du serveur puis l'appel des outils. Chaque requête est autonome et porte sa version du protocole et les capacités du client. La présentation compare une connexion locale via stdio à une connexion distante via Streamable HTTP. Elle précise aussi ce que MCP standardise, sans remplacer les API utilisées par le serveur ni le mécanisme de tool calling du modèle.

L'exemple `create_issue` sert de point de départ pour découvrir les autres primitives du protocole. Les ressources donnent accès à du contenu, comme le README d'un dépôt, tandis que les prompts fournissent des modèles de demande réutilisables pour une revue de pull request. Ces exemples distinguent l'annonce d'une capacité de l'autorisation de l'utiliser, et l'accès à une ressource de son ajout au contexte du modèle.
